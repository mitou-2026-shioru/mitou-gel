# ことば入力・時間窓・相棒UI

## 正規化2軸と時間窓

出力は常に温度・硬さの2成分を持つ `[0,1]²` のベクトルです。℃や圧力を直接送るものではありません。

1. Watch / 模擬心拍: 30秒心拍平均とベースライン差 → arousal → 触覚候補。
2. 音声 / テキスト: 声の特徴と、日本語文字起こしの辞書・簡易否定ルールを別々に解析 → 選択モードで融合 → 触覚候補。
3. 自動入力では、2秒周期で候補を採取し、直近10 / 30 / 60秒以内のサンプルを平均して送信。
4. 手動入力は平均を通さず2軸を直接指定。開始操作と停止操作は周期を待たず送信。
5. 時間窓が未充足なら取得済みのサンプルを平均。遅延で採取できなかった周期を架空のサンプルで埋めません。時間重み付き積分ではなくサンプル平均です。

周期は `ContinuousClock` の固定期限で管理します。処理時間を2秒に足さず、遅れた期限は飛ばして連続送信を避けます。HealthKitの補助取得は別Taskで行い、待ち時間が送信を止めないようにしています。

モード・時間窓変更、有効な入力の欠落、通信異常、アプリのバックグラウンド移行は出力を停止します。心拍・文字は30秒、声の特徴は6秒以内の入力だけを使用します。声は周期的な有声音の手がかりも必要で、無音・手がかり不足は「声だけ」の出力を継続しません。「ことば＋声」では新鮮な文字へフォールバックします。復帰後の再開は手動です。停止要求が届かない場合に備え、M5Stack側にも6秒TTLと独立した物理保護が必要です。長い平均窓を選んでも、古い入力を使って出力を継続しません。

「ゲル」の2軸グラフは送信候補の履歴です。受理された目標・実測温度・実測圧力は別欄で確認します。CSVには窓長・サンプル数・表現の数値、声の特徴、分類確率とラッセル座標、測定時刻・強さの基準・使用モードを記録し、音声や文字起こし本文は含めません。分類結果と送信指令は別の列です。

## 入力の選択と触覚融合

入力モードでWatch・模擬心拍・ことば・手動を選択します。Watchの心拍経路と、ことばの声・文字経路は排他的です。モード変更時には録音・出力を停止し、入力履歴と触覚時間窓をリセットします。

| 入力 | 温度候補 | 硬さ候補 |
|---|---|---|
| Watch / 模擬心拍 | `0.25 + 0.5 × 心拍arousal` | `心拍arousal` |
| 声だけ | `0.35 + 0.30 × 発話の活動率` | `0.15 + 0.75 × (0.55 × 相対強さ + 0.45 × 抑揚)` |
| ことばだけ | `0.25 + 0.5 × 文字valence` | `文字arousal` |
| ことば＋声 | 文字の温度候補 | `0.35 × 文字arousal + 0.65 × 声の硬さ候補` |
| 手動 | 指定値 | 指定値 |

心拍arousalは`clamp(0.5 + (直近30秒の心拍平均 - 個人ベースライン) / 60, 0, 1)`です。文字valence / arousalは日本語の手がかり辞書と簡易否定から求める0〜1の表現パラメータです。学習済み音声分類のラッセル座標は別の表示・記録経路へ渡します。

「ことば＋声」の融合は、新鮮な声と辞書の手がかりを持つ文字がそろった場合に適用します。文字がない・手がかりがない場合は声の候補を使い、声がない場合は新鮮な文字の候補を使います。文字だけで手がかりがない場合の候補は中立`(0.5, 0)`です。有効な入力がない場合は出力を停止します。

自動入力の候補は10 / 30 / 60秒の時間窓でサンプル平均し、温度・硬さを0〜1に収めて2秒周期で送信します。

## マイク入力

- 録音カテゴリは`AVAudioSession.Category.record`。通常録音は`.default`、特徴計測は`.measurement`のモードを使用します。
- 初期設定は「通常録音」「画面側」。録音開始時に内蔵マイクを優先選択し、公開されているデータソースから画面側・下側・内蔵自動を選択します。画面側がない場合は下側、次に利用可能なソースへフォールバックします。
- 「ことば」右上の音声設定でマイク処理・向きを選択します。「診断表示」を有効にすると、`currentRoute`による実際の入力ポート・データソース、入力サンプルレート・チャンネル数、RMS・peakのdBFS、受信秒数、解析待ちで破棄したバッファ数を表示します。
- レベルメーターはRMSの−70〜−10 dBFSを0〜1に変換します。これは表示用の変換で、音声サンプルの増幅は行いません。
- 音声を16kHzモノラルへ変換し、声の特徴・音声分類には2秒窓、文字起こしには8秒窓を使用します。
- 文字起こしの採用条件は窓全体のRMSが−47 dBFS超、または活動時間0.4秒以上かつ有声音時間0.3秒以上です。小さい声と間を含む窓も有声音の手がかりから採用します。
- 録音中に入力経路やサンプルレートが変わった場合は停止し、利用者の操作で再開します。マイク処理・向きの変更は録音停止中に行います。

[Appleのマイク選択仕様](https://developer.apple.com/library/archive/qa/qa1799/_index.html)、[測定モード](https://developer.apple.com/documentation/avfaudio/avaudiosession/mode-swift.struct/measurement)に対応する設定を使用します。

## 声の特徴による触覚候補

触覚候補には軽量な信号処理を使います。このDSP経路と、学習済みモデルによる音声分類は別処理です。音声分類の確率・ラッセル座標は表示・記録用で、触覚指令へ直結させません。

- 「声だけ」: Whisperモデルの準備・ダウンロードなしでマイクを使い、声の特徴だけを触覚へ割り当てます。
- 「ことばだけ」: 既存の文字入力・Whisper文字起こしと日本語辞書を使い、声の特徴をマッピングから除外します。
- 「ことば＋声」: 両経路を利用します。文字に辞書の手がかりがあれば、温度は文字のvalence、硬さは文字由来35%＋声由来65%。文字がない／手がかりがない場合は声のみへフォールバックします。

16kHzモノラル音声の2秒窓から、音がある割合、有声音検出率、強さ（活動フレームの中央値、dBFS）、高さの中央値、抑揚幅（半音単位の標準偏差）を取得します。高さは自己相関で推定し、絶対的な高さから感情・性別を決めません。解析はバックグラウンドTaskで行い、停止・入力変更後の古い結果は採用しません。

```text
有効な声 = 音がある割合 >= 0.20 かつ 有声音検出率 >= 0.15
相対的な強さ = clamp(0.5 + (dBFS - 基準dBFS) / 30, 0, 1)
抑揚 = clamp(抑揚幅 / 6, 0, 1)
声の温度候補 = 0.35 + 0.30 × 音がある割合
声の硬さ候補 = 0.15 + 0.75 × (0.55 × 相対的な強さ + 0.45 × 抑揚)
手がかり不足 → 中立候補 (0.5, 0)、新鮮な声入力としては扱わない
```

初期の強さの基準は−30 dBFSです。普段の声で「いまの声の強さを基準にする」を押すと、その窓を相対強さ0.5にします。基準はアプリ終了まで保持します。温度には発話の連続性、硬さには相対的な強さ・抑揚を割り当て、上記の式と重みで触覚候補を生成します。

声の特徴は自己相関と活動フレームの統計から抽出します。音がある割合と有声音検出率を入力の採用条件として使用します。

使い方は「ことば」→「声だけ」→「話しかける」→マイク許可→声の特徴を確認。M5Stack接続後の出力は「ゲル」で別途開始します。表現モードを変えると録音と物理出力が停止し、両方とも手動で再開します。

## 学習済み音声分類とラッセル座標

`tiny-lm/public/circumplex-model.json`の学習済みMLPをCore MLへ変換し、iPhoneへ同梱します。構造は標準化済み68特徴 → 64ユニットReLU → 6クラスsoftmaxです。分類対象はanger / disgust / fear / joy / neutral / sadness。Whisperによる文字起こしとは独立に動作します。

16kHzモノラルの2秒窓に対し、2048サンプルのフレーム、512サンプルのhopで強さ、ピッチ、輪郭、帯域比、スペクトル形状などを抽出します。Python版の特徴量・推論結果との一致をテストします。無音や有声音の手がかりがない窓には感情ラベルを表示しません。録音停止・入力切替後の古い結果は破棄します。

ラベル確率を上流モデルのプロトタイプへ確率加重投影し、valence / arousalを`[-1,1]`で保持します。分布の尖りには正規化エントロピーを使用し、参考表示の平滑化には次元別の重み、時間減衰、中立事前値、外れ値抑制を使います。この値は認識精度や話者の実感の確率ではありません。

```text
Audio → 68 acoustic features → Core ML classifier → label probabilities
                                               ↓
                              Russell coordinates / AffectState
                                               ↓
                                     UI・CSV（参考表示）

VoiceFeatures / ConversationSignal → ExpressionMapping → HapticState → M5Stack
```

**認識座標と温度・硬さは異なる表現空間です。** ラッセル座標はUI・CSVへ、声・文字の特徴はExpressionMappingへ渡します。音声分類モデルと触覚表現ポリシーを分離し、分類モデルの差し替え時も触覚指令の生成経路を維持します。

このアプリは68特徴MLPを音声分類に、WhisperKit対応モデルを文字起こしに使用します。分類モデルと文字起こしモデルはそれぞれ独立した入出力を持ちます。

移植元のrevision・SHA-256・変換検証結果は`iOS/Models/VoiceCircumplex.json`に保存します。上流リポジトリにLICENSEファイルはありません。モデルを配布する際は上流の利用条件を確認してください。

## 端末内の日本語音声認識

- iPhoneのみWhisperKit 1.1.0をリンクし、Core MLで推論。Watchには音声モデルを積みません。
- 標準は多言語Base。Tinyを軽量実験用、large-v3 turboの626MB版を精度重視の選択肢にしています。Turboはメモリ・ストレージ・読み込み時間を多く使います。
- 初回は「ことば」→「モデルをダウンロード」。モデルとトークナイザの取得にインターネットが必要です。準備済みの正常なキャッシュならオフラインで再読み込み・推論できます。
- ダウンロード先はArgmax公式の `argmaxinc/whisperkit-coreml`。モデルはApplication Supportに保存し、バックアップ対象から除外します。準備中にアプリを終了した場合は再試行してください。
- 「話しかける」でマイク権限を求めます。16kHzモノラルへ変換し、8秒分ごとに日本語で認識します。8秒未満の末尾は停止時に破棄します。
- 無音に近い窓は認識せず、遅い推論では未処理窓を最新1件に置き換え、無制限に音声を蓄積しません。置換数を画面に表示します。
- 一度に推論するのは1窓。停止・モード変更後の古い結果は採用しません。30秒以上遅れた結果も入力として採用しません。
- 音声はメモリ内で処理します。中断・バックグラウンド移行では録音を停止し、CSVには特徴量・分類確率・指令値を記録します。
- 認識結果の更新間隔は音声窓8秒と端末内の推論時間で決まります。

### 互換Core MLモデルの持ち込み

日本語Whisper系モデルをCore MLで端末内実行するためのモデル読み込み機能を備えています。

「互換Core MLフォルダを持ち込む」は `MelSpectrogram`・`AudioEncoder`・`TextDecoder` のmlmodelc / mlpackageを含むWhisperKit互換フォルダをコピーして読み込みます。必要に応じて対応するtokenizer.json等を同じフォルダに含めてください。読み込み対象はWhisperKitのモデル構造・入出力・トークナイザに対応するCore ML形式です。

持ち込みモデルはアプリ起動中に選択し、再起動後は再選択します。コピーと公式モデルキャッシュはアプリ削除まで残ります。

## 簡単な表現分析

「ありがとう」「安心」「緊張」「不安」などの手がかりと直後の簡易否定を使った探索用ルールです。

```text
temperature = 0.25 + 0.5 × valence
stiffness   = arousal
手がかりなし → temperature = 0.5, stiffness = 0
```

値は触覚候補を生成するための表現パラメータです。複数の手がかりを平均し、一致した単語を根拠として画面に表示します。手がかりのない文章は中立候補として扱います。音声の強さ・抑揚による触覚候補と、学習済みモデルによる音声分類は別経路で処理します。

文字入力はモデル・マイクなしで使えます。まず「安心」「緊張」のサンプルで触覚候補の差を確かめ、M5Stackへつないで手動で出力を有効化します。

## デザイン

通常画面は相棒、入力選択、開始・停止、入力結果、温度・硬さ指令を中心に表示します。説明文と常設の技術情報を除き、マイク・モデル設定は「ことば」右上の音声設定へまとめています。

診断表示は初期状態でオフです。「設定」または音声設定から有効にすると、マイクのdBFS・受信状況、声の特徴、分類確率、ラッセル座標、心拍の変化・傾向、デバイスの受理値を確認できます。エラー、出力状態、停止操作は診断表示の設定に関係なく表示します。安全・プライバシー情報は「設定」内に配置します。

オリジナルのゲルの相棒「ぷに」をSwiftUIのShapeで描画しています。点の目・小さな笑顔・頬・有機的な輪郭、紙色の背景とラベンダー／セージ／コーラルを使い、研究ツールの状態表示と親しみやすさを両立します。特定サービスのロゴやキャラクターはコピーしていません。

iOS / Watchのアプリアイコンも同じShapeから生成し、各ターゲットのasset catalogへ組み込んでいます。[Appleの単一画像アプリアイコン仕様](https://developer.apple.com/documentation/xcode/configuring-your-app-icon)に沿った1024px素材で、UIと同じオリジナルキャラクターを使います。

温度で色、硬さで形が変わり、呼吸・まばたき・聞いているときの小さな揺れを追加。Reduce Motionではアニメーションを抑制し、VoiceOverに指令値と状態を伝えます。Watchは計測ページとiPhoneの触覚プレビューページを分け、20秒更新がなければ待機表示に戻ります。

[デザイン検討図](design-preview.png) は共有の実装済みキャラクターを使ったオフスクリーンSwiftUI描画で、画面配置の検討に使用します。

## MacでCore ML経路を再検証する

アプリにリンクするWhisperKit製品だけを使うスモークテストを用意しています。M5へは送信せず、生成した命令は `enabled=false` です。

```sh
cd /Users/kataiwa/mitou-gel
say -v Kyoko -o /private/tmp/gellink-japanese-test.aiff \
  'ありがとう。今日は安心してリラックスできました。少し緊張していたけど、いまは落ち着いています。'
env DEVELOPER_DIR=/Applications/Xcode_27.1_RC.app/Contents/Developer \
  swift run --package-path tools/asr-smoke ASRSmoke \
  /private/tmp/gellink-japanese-test.aiff --download --cache /private/tmp/gellink-asr-models

sandbox-exec -p '(version 1)(allow default)(deny network*)' \
  tools/asr-smoke/.build/debug/ASRSmoke \
  /private/tmp/gellink-japanese-test.aiff --cache /private/tmp/gellink-asr-models
```

MacでTinyによる合成日本語音声1例の認識と、通信を禁止した別プロセスでのキャッシュ再読み込み・認識を確認済みです。
